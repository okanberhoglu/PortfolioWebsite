ChatMoonVLM

A web-based Visual Question Answering application powered by the Moondream vision-language model — running locally, privately, on consumer hardware.

Overview

Project Overview

ChatMoonVLM is a web-based Visual Question Answering (VQA) system that lets users upload images and ask natural-language questions about them through an interactive chat interface. The system is built around Moondream, a small open-source vision-language model designed to run efficiently on consumer-grade hardware — including laptops and mobile devices — without requiring external API calls or cloud services.

This approach makes it a practical privacy-preserving alternative to proprietary VLMs such as GPT-4V or Gemini, particularly in scenarios where low latency or offline operation are priorities. The application is built with the Streamlit framework and organized around a modular, service-oriented architecture with persistent chat history and in-memory image embedding caching.

The entire application is containerized with Docker. Moondream model weights are baked into the Docker image at build time, so the container starts instantly without any download step. The published image is available on Docker Hub and runs with a single command, mapping port 8501 for browser access.

Architecture

System Architecture

The application follows a modular, layered design with clear separation between the UI, service, and model layers. The entry point initializes session state, manages page navigation between the main and chat pages, and ensures the model is loaded on startup. A dedicated model installer script pulls a pinned Moondream revision from Hugging Face Hub during Docker build, so the container ships with weights already present.

1
Image upload

User uploads an image on the main page. ImageService saves it to disk and returns a reference for display and model input.

2
Embedding encoding

The Model class encodes the uploaded image into a visual embedding once and caches it in memory, avoiding repeated encoding overhead for subsequent questions.

3
Question input

The user types a natural-language question on the chat page. The input is sent to the model layer along with the cached image embedding.

4
Answer generation

Moondream processes the question and cached embedding on GPU or CPU (auto-detected) and returns a natural-language answer.

5
Session persistence

ChatService appends the Q&A pair to a JSON session file. History survives application restarts and remains accessible from the main page.

UI Layer
  • MainPage — image upload, session history list, and "Start New Chat" button built with Streamlit components
  • ChatPage — active chat interface rendering the image, Q&A history, and question input field
  • Session state — Streamlit session state tracks active page and loaded model across reruns
Service & Model Layer
  • ChatService — creates sessions, serializes and retrieves Q&A history as JSON files on disk
  • ImageService — saves uploaded images to disk and loads them for display or model input
  • Model (Moondream) — wraps the VLM with GPU/CPU adaptive loading and in-memory embedding caching per image
  • Docker — containerizes the full stack with model weights baked in at build time for zero-config deployment
Features

Key Features

Local, privacy-preserving VQA — all inference runs on-device with no external API calls, making the system suitable for sensitive images or offline environments.
Multi-turn chat per image — users can ask multiple follow-up questions about the same uploaded image within a single session without re-encoding the visual context.
Persistent chat history — all sessions are serialized to JSON and survive application restarts, letting users revisit previous image conversations from the main page.
In-memory embedding caching — the image embedding is computed once per session and reused for all subsequent questions, significantly reducing per-query latency.
GPU/CPU adaptive loading — the model layer automatically detects available hardware and loads Moondream onto GPU when present, falling back to CPU transparently.
Modular service-oriented architecture — clean separation between the UI, ChatService, ImageService, and Model layers makes each component independently testable and replaceable.
Zero-config Docker deployment — the full stack including model weights is baked into the Docker image at build time, so the application starts instantly with a single docker run command.
